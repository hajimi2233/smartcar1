# 16点候选v2：同侧点对离线验证

上排1、3、5、7、9和下排2、4、6、8、10，分别验证全部有向点对，共40组。

两排深度采用之前保存的实测前轴中心。小突出墙体位于示意右侧，上起点、下终点。右侧绕行点向外墙移动30cm，两条低代价线分别远离外侧边墙25cm、30cm。世界坐标不旋转，未修改地图或TF。

使用从车端只读抓取的5cm地图、参数和规划器源码快照。本电脑离线计算：半径1.35m、全局裕度0.05m、车身0.75×0.48m。

## 结果

**40/40成功，无超时。** 每组独立Python进程，无跨点对热缓存。执行入口、沿线、最终转弯三阶段，每阶段预算3秒。耗时包含规划和额外的输出路径静态碰撞、扫掠复查。

- 耗时中位数：0.147s；95分位：0.230s；最大：0.243s。
- 前轴终点最大误差：0.000cm；航向最大误差：0.000°。
- 全路线换挡次数：2～6。规划耗时通过不代表换挡次数最少，本次没有修改全局算法或缩小碰撞裕度。

## 边界

只验证同侧标准中心位姿的B区域约束场景，上排朝向世界106.5°、下排−73.5°。不是16点任意互通，不包含完整起终点巡检顺序、动态雷达、随机位姿偏移及实车执行误差。电脑耗时不是车端实时耗时。

16点另做静态位姿检查：巡检点按进入通道方向，绕行点和起终点按场地四个轴向方向；结果见pose_checks.json。这不证明点间任意方向都能规划，也不支持原地掉头。

坐标与线：preview_points16.json；16点CSV：points_front.preview.csv；批量结果：pair_results.json；完整路径：pair_起点_终点.json。

## 起终点朝向提醒

巡检点10个全部通过其进入通道方向的静态检查；4个绕行点全部通过场地四轴方向检查。起点和终点沿蓝线方向的车身位姿可行。若起点朝世界106.5°、或终点朝世界−73.5°，后轴及车尾会靠外侧墙过近，静态检查不通过。因此保持现有点位置时，建议起点朝世界16.5°、终点朝世界−163.5°，即沿蓝线方向。此建议没有修改现有车端起终点朝向。
