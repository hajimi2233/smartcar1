本文合并原 C 程序的三份说明。以下运行命令和相对数据路径均以 `local_project/inspection_c` 为工作目录。该程序尚未与单点导航接成完整任务。


## C 程序使用

## 纯 C 巡检顺序规划器

不依赖 Python、ROS 或第三方库。当前是文本验证程序；规划核心在 `planner.c`，输入输出在 `main.c`。

当前版本为 **V6**，读取 26 点 CSV，以前轴中点为参考，自动推导通道朝向；提供前进/倒车模式、JSONL 导出和纯 C 反馈状态机。入口与准备点合并，取消列内中间停车点。详细说明见 本文“26 点导入与动作”部分。默认坐标是演示数据，不是实车标定结果。

### 直接运行

Windows 上双击 `run.cmd`，窗口应显示 V6。程序从同目录读取 `map_info.txt` 和 `points.csv`。替换这两个文件后输入 `r` 重新导入；每次规划前也会自动重读。旧版 `motion_map.txt` 已不使用。旧窗口请退出后重新启动。

输入示例：

```text
A1B2A3A4
B1B2A3A4A5A6A7A8A9A10
```

支持 2、4、6、8、10 个点，用于从小场景逐步验证。编号必须从 1 连续到最大编号，每个编号只出现一次；A/B 不区分大小写，允许空格和英文逗号。输入 `q` 退出。

PowerShell 中也可以一次运行一个案例：

```powershell
.\inspection_planner_v6.exe "B1B2A3A4A5A6A7A8A9A10"
```

输出巡检顺序：

```text
start -> 1 -> 3 -> 4 -> 2 -> 6 -> 5 -> 7 -> 8 -> 10 -> 9 -> end
```

`A1B2A3A4` 的完整行程是 `start -> 1 -> 2 -> (1) -> 3 -> 4 -> end`。括号中的点仅借道、不再次巡检或播报。B 点事件包含进入与原侧退出。

### 本版的场地假设

```text
        +----上方公共通道（起始侧）----+
        |  | 1 | 3 | 5 | 7 |  9 |  |
        |  | 2 | 4 | 6 | 8 | 10 |  |
        +---------下方公共通道--------+
```

- 每列内部上下相连；列之间有墙，仅能通过上方或下方公共通道换列。
- A 允许双向通过；B 可从任意可达侧进入巡检，但必须原侧退出，不能贯穿。
- 同一区域只巡检一次，已完成的 A 可以重复借道。
- 起始侧固定为上方，按列号递增推进；换侧后优先补检距当前列最近的待办点（列号差最小，相同则小编号优先）。
- 两端外侧公共通道都连接上下两端，不需要穿过巡检区。无新列可处理而另一侧有遗漏时，从距当前列较近的外侧端换侧（相同则右侧优先）。
- 左右命名按用户指定的编号示意：1/2 端为左侧，最右侧为右侧；图中的字母区域标签与输入的 A/B 状态不同。
- 全部为 B 也可以巡检完整：上侧顺序巡检后绕外侧，下侧反向补检。
- 就近以等间距列号估算，不使用实测米数，也不宣称全程最短。
- 起点和终点从 CSV 导入；起点需位于上方公共区，终点需从下方公共区可达。不会根据任意起点自动改变起始侧。
- 完成全部巡检后，在下方就沿下方公共通道去出口；在上方就先沿上方通道走到左侧，从外侧绕到下方，再去出口。回程不进入任何巡检区。
- 生成拓扑动作和导入坐标对应的目标指令，不求连续可驾驶轨迹。车辆到达反馈由导航执行端接入；文本中规划到终点不代表实车已经到达。

修正案例 `A1A2B3B4A5B6A7B8A9B10`：

```text
巡检顺序：start -> 1 -> 2 -> 4 -> 6 -> 8 -> 10 -> 9 -> 7 -> 5 -> 3 -> end
完整行程：start -> 1 -> 2 -> 4 -> 6 -> 8 -> 10 -> [右侧外部绕行]
          -> 9 -> (9) -> 7 -> (7) -> 5 -> (5) -> 3 -> [左侧外部绕行] -> end
```

9、7、5 从上方巡检后，其下方均为已巡检的 B，所以各自原路返回上方。不是穿过 10 去 9。

### 核心接口

```c
int parse_layout(const char *text, Layout *layout, char *error, size_t error_size);
int make_plan(const Layout *layout, Plan *plan);
```

`Plan.order` 是只包含首次巡检的编号序列；`Plan.events` 还包含静默借道和外侧绕行动作。先检查 `kind`：`EVENT_POINT` 为点位动作，`EVENT_OUTER_LOW/HIGH` 为左/右侧外部绕行，绕行事件的 `point` 为 0，不能当巡检目标发送。点位事件中的 `inspect` 为 1 时需要巡检，为 0 时仅通过。`entry_side` 表示从点的上方（0）或下方（1）接近，B 事件执行后回到进入侧。外侧绕行事件中的 `entry_side` 表示换侧前所在的公共通道。

后续接入 ROS 1 时可以由 C++ 节点封装 C 规划核心，逐项下发任务并等待执行完成反馈。当前 `visited` 只是规划过程的模拟记录，实车完成状态需要由执行反馈确认。

V3 新增 `EVENT_END`：表示沿下方公共通道到达左侧出口，`point=0`、`inspect=0`，只能作为最后一个事件出现。`Plan.order` 仍只包含巡检编号，不将终点作为第 11 个巡检任务。`Plan.complete` 表示已经规划好全部巡检及合法终点路线。

### 验证

`tests.c` 检查 2/4/6/8/10 点的全部 1364 种 A/B 组合，以包含两端外侧连接的独立物理路网搜索作为对照，同时检查全部点可巡检、每一步没有横穿隔墙、没有穿过 B、巡检不重复、借道不播报，以及回归案例、外侧换侧事件和非法输入。每种布局还验证：终点事件只出现一次且位于末尾，前往终点前所有任务都已完成，最终位置为左侧下方出口。

命令行退出码：0 为巡检全部完成，1 为输入或内部错误，2 为部分巡检点不可达。交互模式允许连续尝试多个输入。


### 点位与简化动作

点位仅含名称、x、y，共 26 个。所有目标使用前轴中点为参考。巡检点是每区唯一的中心点，从两个方向进入共用同一坐标。程序使用本列两个通道外入口坐标推导朝向，因此地图整体旋转不影响这个计算。

| 阶段 | 行为 | 模式 |
|---|---|---|
| ALIGN | 在通道外入口点对齐车头，准备进入 | AUTO |
| INSPECT | 前进到巡检区中心并等待巡检完成 | FORWARD_ONLY |
| PASS | 通过通道，前进到另一端的通道外入口点 | FORWARD_ONLY |
| RETREAT | 原路倒车到通道外入口点，不重复播报 | REVERSE_ONLY |
| OUTER | 公共区外部绕行 | AUTO |
| EXIT | 前往导入的终点 | AUTO |

不再生成 ENTER、CLEAR 或列内连接点停车指令；枚举旧值仅为源码兼容保留。通道外入口点同时承担准备和退出功能。

`A1B2A3B4` 现在生成 11 条命令：

```text
col1_top_entry   ALIGN     AUTO
inspect_1        INSPECT   FORWARD_ONLY
inspect_2        INSPECT   FORWARD_ONLY
col1_top_entry   RETREAT   REVERSE_ONLY
col2_top_entry   ALIGN     AUTO
inspect_3        INSPECT   FORWARD_ONLY
inspect_4        INSPECT   FORWARD_ONLY
col2_top_entry   RETREAT   REVERSE_ONLY
map_right_top    OUTER     AUTO
map_right_bottom OUTER    AUTO
end              EXIT      AUTO
```

从 2 倒车到入口会经过已检的 1，但不在 1 或列内连接点额外停车。完整拓扑行程仍显示 `(1)`，以说明借道关系。B 的含义仍是到其中心巡检后退出，不是把 B 中心当作不能触及的障碍。

### 起终点、地图与几何限制

- `start` 从 CSV 读取并写入计划信息，不再固定为 1 外的入口。车应已在该起点附近，初始姿态和定位由执行端提供；程序不会先命令车回起点。
- 原路线起始侧仍是上方公共区，终点必须从下方公共区可达。仅更换坐标不会自动改变这套拓扑。
- 每列是直通道，两个巡检中心需依次位于两入口之间，距入口连线的垂距不超过 0.05 米。这个导入校验阈值不是车辆定位精度、控制容差或安全距离。
- 输入数据可旋转、平移，列间距也可不同；原先的补检顺序仍以列号差判断远近，尚未按实际米数重新优化。
- 没有墙体地图、车辆轮廓或转弯半径的几何验证，不能仅凭导入成功认定实车路径可行。

### 给导航执行组

ROS1 接口草案为 `ros1_interface/ExecuteMotion.action`，未提供 ROS 构建或执行服务端。本机仅编译纯 C 规划程序。

- `target_id` 现在是固定点名，同一位置可以多次出现；单条命令以本轮 `task_id` 区分，跨轮以 `mission_id` 区分。
- `map_id`、`map_version`、`frame_id` 来自元数据文件。`target_reference=front_axle_midpoint` 必须落实到目标参考点转换。
- `yaw_rad` 是程序从入口推导的车头朝向，用户不需要填写。`enforce_yaw=true` 用于入口对齐和通道段；OUTER、EXIT 为 false，其 yaw 占位值应忽略，不能强制最终朝向为 0。
- `AUTO + PUBLIC_ONLY` 只在公共区导航，不允许为抄近路进入巡检区。`FORWARD_ONLY` 仅前进或停车；`REVERSE_ONLY` 仅倒车或停车，通道段保持车头方向，不能掉头后前进。
- `CHANNEL_WITH_PORTALS` 和 `column_id` 指定对应列及其通道外入口，执行端必须维护这些范围，目标点列表本身不能阻止导航抄近路。
- 所有段仍约定 `stop_at_goal=true`。INSPECT 的成功反馈必须同时代表到位及识别、播报完成；退回或经过已检区不播报。
- 无法到达、无法满足进退模式等情况返回失败；不自动跳过任务。
- JSONL 的 `plan_only=true` 表示只是待执行目标，无实车验证。`start_x/start_y` 是计划起点，不是实时定位值。

普通 move_base 目标不会自动理解这些扩展字段，仍需执行层对接。更换坐标文件只影响之后生成的计划，不修改执行中的计划。

### 反馈和编译

`session.c` 保留反馈状态机：

```c
MotionSession session;
motion_session_begin(&session, &plan, new_mission_id);
const MotionCommand *cmd = motion_session_current(&session);
/* 下发 cmd，收到真实反馈后： */
motion_session_ack(&session, feedback_mission_id, feedback_task_id, success);
```

成功才推进；错误或旧任务编号不推进；失败停止。会话持有计划指针，执行期间不能释放或修改该计划。C++ ROS 包装层使用 `extern "C"` 引用 C 接口，.c 文件按 C 编译。

双击 `build.cmd` 编译 V6 并运行检查：1364 种拓扑布局，2728 次运动检查（每种布局使用原始和旋转地图），以及缺点、重名、非法数值、几何错误、元数据错误与导入失败不覆盖原内存数据的验证。这些不是实车或导航仿真测试。


## 建图组交接格式

## 建图组点位数据交接说明

本文约定建图组向巡检任务规划组提供的数据。使用文件交接：建图组导出，规划组导入；坐标更新后重新导入即可，不需要专门建立 ROS 话题或节点传输。

### 1. 需要交付的文件

请提供两个 UTF-8 文本文件，并放在同一个文件夹中：

| 文件 | 内容 |
|---|---|
| `map_info.txt` | 地图标识、版本、坐标系和单位 |
| `points.csv` | 固定点名及其 x、y 坐标 |

点位必须来自导航执行端使用的同一张地图、同一坐标系。更换地图原点、旋转地图或重新建图后，应更新版本并重新核对全部点位。

完整栅格地图仍按导航组要求交付给导航组，本次任务规划点位文件不代替导航地图。

### 2. 坐标的统一含义

- 所有目标坐标均指 **左右前轮连线的中点，即前轴中点的目标位置**。
- 单位为米，使用实际地图坐标，不使用图片像素坐标，不另行平移或旋转坐标。
- 巡检目标取各巡检区域的中心，每区一个，共 10 个。两侧进入使用同一个坐标。
- 点位表只提供 `x、y`，**不需要逐点提供朝向、前进/倒车模式或语音播报指令**。
- 车头朝向由导航执行端根据入口和通道关系处理：进入前对齐，通道内前进巡检，原路退出时保持朝向倒车。
- 如果导航定位使用车体中心或后轴中心，参考点转换由导航执行端实现，不能把这些目标直接当成另一个参考点的坐标。

标定时应与导航、识别组确认：前轴中点停在区域中心时，车辆沿通道对齐，两个前轮位于巡检区内且有误差余量，并能完成识别。规划程序不实时检查前轮与区域边界。

### 3. 区域编号与点位清单

沿用任务规划中的编号关系：

```text
                 上方公共区域
          1     3     5     7     9
          2     4     6     8    10
                 下方公共区域
```

每列上下连通，相邻列之间有墙。这里的“上、下、左、右”是任务示意图中的方向，**不要求对应地图的 +y、-y、-x、+x**。

如场地原图使用 A～J，请先确认与上述 1～10 的对应关系，再填写数据，不要按图片左右位置自行反转编号。A/B 可通行状态是另一类任务输入，不是本表的区域名称。

#### 3.1 通道外入口点：10 个

每列上、下各一个，兼作进入前准备点和倒车退出目标，不再另设一套准备点。

| 点名 | 所在位置 |
|---|---|
| `col1_top_entry` | 1 所在端的通道外 |
| `col1_bottom_entry` | 2 所在端的通道外 |
| `col2_top_entry` | 3 所在端的通道外 |
| `col2_bottom_entry` | 4 所在端的通道外 |
| `col3_top_entry` | 5 所在端的通道外 |
| `col3_bottom_entry` | 6 所在端的通道外 |
| `col4_top_entry` | 7 所在端的通道外 |
| `col4_bottom_entry` | 8 所在端的通道外 |
| `col5_top_entry` | 9 所在端的通道外 |
| `col5_bottom_entry` | 10 所在端的通道外 |

选在通道中心线延长线上的公共区域内。与导航组确认：倒车到此点时已退出巡检区，且整车具有后续转向空间；不要只把点放在墙端或区域边界上。

#### 3.2 巡检停车点：10 个

点名为 `inspect_1`、`inspect_2`，依次到 `inspect_10`，分别填写对应巡检区域中心的坐标。不按接近方向拆成两个点，不需要额外提供每列两个巡检区之间的连接点。

#### 3.3 外部绕行点：4 个

| 点名 | 所在位置 |
|---|---|
| `map_left_top` | 地图左侧（-x）外侧通道与上方公共区的连接位置 |
| `map_left_bottom` | 地图左侧外侧通道与下方公共区的连接位置 |
| `map_right_top` | 地图右侧（+x）外侧通道与上方公共区的连接位置 |
| `map_right_bottom` | 地图右侧外侧通道与下方公共区的连接位置 |

left/right 以地图坐标系为准：RViz 俯视图中 +x 向右。不按 1/2、9/10 编号命名。点应位于可行驶公共区域，并与导航组核对整车通行及转弯空间，不取墙角本身。规划程序导入时会按 `inspect_1` 落在哪一侧，自动把绕行点对应到小编号端/大编号端。

#### 3.4 起点和终点：2 个

- `start`：比赛固定起始位置的前轴中点坐标。
- `end`：比赛结束停车位置的前轴中点坐标。

实际起终点以比赛布置为准，不沿用旧演示程序的假定坐标。当前路线约定起点在上方公共区，终点可从下方公共区到达；若比赛改变这一连接关系，需要通知规划组修改拓扑。起点朝向和运行时车辆位姿由定位、导航组处理；填写 `start` 并不等于完成机器人初始定位。若之后明确从实时当前位置开始，可另行约定省略固定起点；本次交接先保留。

**本次点位表合计 26 行数据：10 个入口点 + 10 个巡检点 + 4 个绕行点 + 起终点。**

### 4. 文件格式

`map_info.txt` 示例（以下为格式示例，请替换地图名称及版本）：


`points.csv` 第一行必须为表头，使用英文逗号。下面列出全部固定点名，`<x>`、`<y>` 是占位符，交付时必须替换成实际数字：

```csv

col1_top_entry,<x>,<y>
col1_bottom_entry,<x>,<y>
col2_top_entry,<x>,<y>
col2_bottom_entry,<x>,<y>
```

### 5. 后续更新与职责

- 点名保持不变，不缺失、不重复；坐标修改后更新版本，重新交付这两个文件。
- 点位表不包含 A/B 可通行状态、巡检顺序、前进/倒车模式或播报设置，这些由任务输入和规划程序处理。
- 本次不要求额外导出巡检区边界、多余中间点或逐点朝向。
- 文件先由规划端完整导入、核对后，再用于下一轮任务；执行中的任务不因文件被修改而自动改变。

V6 已支持上述文件格式，替换文件后输入 `r` 可重新导入，每次生成路线前也会自动读取。旧的 14 参数 `motion_map.txt` 不再使用。导航实车执行端仍由导航组实现。

当前导入器要求元数据值使用不超过 63 字符的英文字母、数字、下划线、短横线、句点或斜杠；CSV 使用不带引号的固定点名和数字，支持 UTF-8 BOM。每列要求上入口、奇数巡检点、偶数巡检点、下入口沿直通道依次排列，巡检点到两入口连线的垂距不超过 0.05 米。此阈值用于发现标定数据与直通道模型的明显不一致，不是车辆的到达误差或安全余量；若真实场地不满足模型，请反馈规划组，不要为通过检查而改造真实数据。
