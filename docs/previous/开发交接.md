# 开发交接：当前实现与验收边界

日期：2026-09-21。目录：smartcar1。开发环境：Windows；未访问 Linux Docker、Gazebo 或实车。

## 已实现

- 独立单点导航节点；复用现有 map → odom → base_footprint 定位链，不重启定位、不引入 IMU 或真值里程计。
- 接收 RViz 2D Nav Goal 的位置和四元数朝向，或命令行 X/Y/角度。前轴目标转为后轴控制目标，拒绝未知坐标系、非有限值、无效四元数。
- Hybrid A*，使用前进/倒车圆弧及直线，规划半径至少 1.30 m，有限搜索预算。不移动目标、不减小车身轮廓、不生成原地旋转。
- 地图整车轮廓及轨迹采样碰撞检查；未知区域/地图外阻挡；处理旋转地图原点。
- 分方向 Pure Pursuit 跟踪，换向前通过激光位姿估算确认停车；不跨换向点选前瞻目标。
- 雷达采样时间对应 TF 和雷达外参投影；实时碰撞时停车，暂不自动绕行/重规划。
- 雷达/局部 TF 过期、定位跳变、路径偏差、进度停滞、超时及其他速度发布者出现时停止。墙钟循环不依赖 ROS 定时器随仿真暂停。
- 最终前轴误差不超过 7 cm、朝向误差不超过 4°且静止后才报告 SUCCEEDED；未满足则失败停车。
- 宿主机 nav / goal / cancel / nav-status 入口；RViz 显示新路径；键盘入口拒绝与导航同时启动。

## 本地测试结果

`python -m unittest discover -s tests -v`：12 项测试通过。

导航测试覆盖前后轴换算、圆弧正反运动、后轴点无碰撞但车身碰撞、路径中间障碍、未知/越界、旋转地图、碰撞目标不偏移、半径下限、取消、障碍绕行；在独立自行车运动学模型中测试直行、倒车、90° 转向、同位置改变朝向四组规划+闭环跟踪，达到设定的位置及方向容差。另保留两项键盘行为测试。

Python 文件语法解析、6 个 launch XML、20 个宿主机/overlay/Docker Shell 的 bash -n 检查通过。新增核心模块采用普通文件复制到 devel/lib/smartcar_navigation 并安装到包可执行目录，避免将可导入模块做成 catkin 可执行 relay。

## 尚未验证

Docker 构建、catkin 实际编译/安装、Python 2 + ROS Kinetic 运行、Gazebo 动力学与转向滞后、激光定位误差、图形显示、实际停车距离、实车底盘协议均未验证。离线测试使用 Python 3 和自行车运动学，不代替这些验证。

程序只发 `/sim/cmd_vel`，当前不用于实车。1.30 m 是保守仿真初值，不代表实车已标定。路径不识别巡检区域语义；测试限定在公共区域，不能视为完整比赛导航。复杂场景超预算会失败，跟踪偏差或新障碍停车后需人工确认并重新发目标。
