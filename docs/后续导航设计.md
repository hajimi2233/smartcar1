# 导航实施方案：阿克曼多次换向与巡检分阶段

编制日期：2026-09-19。对象：接手本项目的导航开发人员。

**状态：这是待实施的工程设计与验收依据，不表示下文新增节点、插件和配置已经存在或已经通过实车测试。此次仅新增交接文档，没有改动程序、地图、定位配置或启动脚本。**

## 1. 任务目标与已经确定的路线

车辆定位已由用户确认可用。本次工作只补齐导航与巡检执行，使车辆能够在有限转弯空间中，自动规划前进、倒车的组合动作，最终正对指定通道；随后按巡检规则前进进入、停车巡检、通过或倒车退出。

实施路线固定如下，不再重新比较导航框架：

| 层次 | 确定采用的方案 |
| --- | --- |
| 系统 | Ubuntu 16.04、ROS1 Kinetic、catkin；保留现有 Docker 仿真环境 |
| 定位 | 接入已经工作的纯雷达定位；不要求轮式里程计或 IMU，不重做定位算法 |
| 巡检顺序 | 复用 `local_project/inspection_c` 的 C 规划核心和会话机制 |
| 公共区全局规划 | SBPL XYTheta 状态栅格、ARA*，自定义汽车前进/倒车动作原语 |
| 几何连接 | OMPL Dubins 用于固定方向连接，Reeds–Shepp 用于允许换向的连续边界连接；每条连接必须检查障碍 |
| 公共区执行 | TEB 0.6.14，加本项目的有向分段封装；每段固定前进或倒车，在换向点停稳 |
| 通道内执行 | 后轴参考的双向 Pure Pursuit 直线跟踪，固定行驶方向、低速停车，不自行绕行 |
| 地图约束 | ROS costmap_2d 加本项目的任务范围层；完整车身与转向轮包络碰撞校验 |
| 指令出口 | 一个运动仲裁与约束检查节点，之后通过仿真/实车适配器接驱动 |
| 开发语言 | ROS 接口、插件和控制使用 C++11；原巡检核心仍按 C 编译 |

不采用 Nav2；不把二维 A* 加舵角限幅当作最终汽车导航；不依赖默认旋转恢复；不把 TEB 的软约束直接当成行驶方向或机械能力的硬保证。

**范围边界：**本方案包含外部转场、对准入口、多次换向、通道跟踪、停车、巡检确认及故障停止。图片识别、语音实际播放、底盘电机驱动由对应组提供接口。本方案要求对接这些接口，不重写这些组的业务。

## 4. 统一几何与坐标约定

### 4.1 三个参考点各司其职

- 定位现有 `base_footprint` 原点保持原样，不修改已工作的动态 TF 发布者。
- 新增或复用静态 `nav_base`，原点为后轴中点在地面的投影，x 向车头、y 向左。全局/局部规划、速度计算都使用它。
- 业务目标仍使用 `front_axle_midpoint`。若 URDF 已有该 frame，不重复发布；新增 `nav_base` 也只能有一个静态 TF 发布者。

在车体中心恰好位于两轴中点的现有模型假设下，前轴位于中心前 0.31 m，后轴位于中心后 0.31 m。实车若参考原点不同，只调整固定外参，不改变导航算法。

对车头朝向为 θ 的前轴目标 `(xf, yf)`，后轴目标为：

```text
xr = xf - 0.62 cos(θ)
yr = yf - 0.62 sin(θ)
```

倒车时也按**车头朝向**转换，不把朝向加 π 后错误地当成车头。无强制朝向的目标，必须先生成并选择候选朝向，再做该转换。

TF 主链沿用 `map → odom → base_footprint → nav_base`。不得为补 `/nav/odom` 消息再发布一套 `odom → base_footprint` 动态 TF。

### 4.2 车身与轮胎包络

按车长 0.80 m、前后悬对称推导，后轴参考的车身矩形 x 范围约 `[-0.09, 0.71]`，y 范围约 `[-0.275, 0.275]`。这是车身基准，不足以替代打方向后的轮胎包络。

V1 使用“车身与所有允许舵角下轮胎投影的并集”的固定保守凸包，不随每帧方向改变 footprint。按已给轮距和轮胎尺寸计算，前轮外侧可能接近 y=±0.31 m；生成工具应计算准确凸包并在 RViz 叠加核对，不能仍以直行车宽覆盖所有转向状态。

障碍距离分两层：物理包络加 0.05 m 初始硬余量，外围再设软代价引导。0.05 m 是调试初值，须覆盖定位、控制、地图误差；不得为了“规划成功”自动减少它。全局规划、TEB、最终轨迹校验使用同一包络与余量定义，避免漏算或重复扩张。

### 4.3 转向余量

- `R_measured`：左/右、前进/倒车可靠最小半径中的最大值，全部以后轴中心为参考。
- `R_plan = max(1.10 × R_measured, R_measured + 0.10 m)`，作为默认设计规则。
- 尚未获得可靠半径记录时，离线/仿真暂用 `R_plan=1.30 m`，标记 `radius_calibrated=false`；这不是对实车能力的确认。
- 全局原语、连续连接、TEB、最终输出检查共用 `R_plan`；对应等效舵角上限为 `atan(0.62 / R_plan)`。
- 碰撞余量与转弯半径余量独立设置，不靠篡改实车长宽来实现转向余量。

提高半径可能使部分路线不存在，这是需要如实报告的结果；不能在失败时偷偷切回物理极限半径。

### 4.4 V1 统一参数初值

下表是低速调试配置，不是实车已测性能。相同参数只保留一份配置来源，其他模块引用，不能各写一套数值。

| 参数 | 初值/规则 |
| --- | --- |
| 公共区前进/倒车速度上限 | 0.15 / 0.08 m/s |
| 通道前进/倒车速度上限 | 0.10 / 0.08 m/s |
| 最后接近停车点速度上限 | 0.04 m/s，仍受实际制动空间限制 |

| 加速上限 | min(0.15 m/s², 标定可靠上限) |
| 可靠制动减速度、舵角变化率、停车打方向能力 | 来自标定/已验证仿真参数，不从最大速度反推 |

## 5. 地图与 26 点数据的接入

### 5.1 保留现有点位接口

`points.csv` 继续使用 `point_id,x,y`，包含 start/end、10 个上下入口点、10 个 inspect 点、4 个 map_left/map_right 外侧点。点坐标均为前轴中点目标坐标。

当前 `data/maps/slam_current/points.csv` 已有这 26 个点，同目录 `map_info.txt` 为 map_id=slam_current、map_version=slam_v1、frame_id=map。将这一对文件作为导入候选；`local_project/inspection_c/map_info.txt` 仍是 `map_demo` 示例元数据，不能混用。准备点或语义范围改变后建立新地图批次版本，保持原解析器要求的五个字段：map_id、map_version、frame_id、units=m、target_reference=front_axle_midpoint。

更换地图必须成批切换：地图图像、map.yaml、points.csv、map_info.txt、下述 field_semantics.yaml、nav_manifest.yaml。只允许在 IDLE 状态原子导入；失败保留内存旧批次但不执行新任务，也不回放旧 JSONL。

map.yaml 当前 image 为容器绝对路径，交付时改成与 YAML 同目录的相对图像路径并验证加载。新增 `nav_manifest.yaml` 保存所有输入文件 SHA256、车辆配置哈希、原语哈希、schema_version；不把新增字段塞进旧 C 元数据解析器。

### 5.2 补充语义范围，避免导航抄近路

新增 `field_semantics.yaml`，至少包含：

- 实际允许活动的公共区多边形，左右绕行区域及上下区域的连接关系。
- 每列通道的可行驶多边形、两端物理墙口边界、进入方向与中心线。
- 巡检区域的实际范围、中心点关联、A/B 状态及允许的有向通行关系。
- 入口准备点、直线接入段、退出后的车身净空检查结果。

几何可依据地图和场地尺寸离线标注，但必须可视化检查。CSV 只有点，不能单靠点坐标判断允许范围。A/B 是任务权限，B 区中心仍是需要到达的位置，不能把整个 B 区涂为障碍。

V1 对公共区转场关闭所有列内捷径。通道模式只开放当前列、必要的通道外连接区域及本任务授权的巡检范围。已检区域允许的必要借道保留，播报状态独立管理。

### 5.3 入口准备点的确定方式

保留每个入口一个对外任务点，不要求用户再手填一组准备点。用物理墙口和中心线生成准备点候选，选定后以新地图版本写入那 10 个入口点；**不在运行中悄悄修改 CSV 目标含义。**

准备点应同时满足：进入时可以向内直行；前进穿出到该点时车尾已离开隔墙；倒退出到该点时可以开始公共区转场。完整车身包络和硬余量都必须在公共区域内。

具体生成规则：从物理墙口沿向外中心线，按距离 0.85、1.05、1.25、1.45、1.65 m 生成候选；逐个检查两种车头朝向、直线进入/退出的完整包络。候选只是搜索起点，不是认定所有入口都有这些空地。选可行且转场代价较低的一项；全部失败则报告该入口无法按单准备点模式配置，停止该入口接入，不缩小车身或穿墙。

每个准备点外再派生一段至少 0.35 m 的最终前进直线接入段，作为 ALIGN 路径的一部分，不新增必须停车的业务点。空间不足时应扩大公共区内的找正动作范围或调整准备点候选；实际场地无法满足则该入口方案不通过。

巡检点位置不移动；不因点位过于贴近地图障碍而随意“吸附”到附近空点。START 校验当前位置是否符合任务起点条件，不自动瞬移或发布初始定位；OUTER 点用于约束绕行侧，仍按既有 V1 停车目标处理。

## 6. 运行架构和控制权

```text
现有雷达定位 ── TF / scan / map ──┬─ lidar_odom_bridge → /nav/odom
                                  └─ 全局/局部 costmap

C 巡检核心 → inspection_mission_node → ExecuteMotion action
                                      ↓
                              motion_executor_node
                       ┌──────────────┴──────────────┐
                       │ 公共区 AUTO                 │ 通道 FORWARD/REVERSE
                       │ move_base                   │ corridor_controller
                       │ TaskAwareSBPLPlanner        │ 双向直线跟踪
                       │ SegmentedTebPlanner         │
                       └──────────────┬──────────────┘
                                  motion_guard
                                      ↓
                              sim / real adapter → 驱动
```

上图的新命名为本方案规定的交付名称，不是当前已有节点声明。

### 6.1 节点和插件责任

| 模块 | 必须负责 | 不负责 |
| --- | --- | --- |
| `inspection_mission_node` | 调 C 核心，生成/推进任务，持久化已检状态与巡检确认 | 连续打方向 |
| `motion_executor_node` | 校验地图/目标，选择模式，管理 action、超时、控制权，发起巡检并等待确认 | 自己修改拓扑顺序 |
| `TaskAwareSBPLPlanner` | 汽车原语全局规划、连续边界连接、方向/换向点保留、任务范围约束 | 将不可能路径交给局部层硬追 |
| `SegmentedTebPlanner` | move_base 局部插件，有向分段、停稳换向、TEB 定向封装、轨迹检查 | 擅自进入别列或删掉换向点 |
| `corridor_controller` | 给定直线、目标和方向的闭环跟踪与停车 | 自动掉头、换方向绕障 |
| `lidar_odom_bridge` | 从连续雷达局部位姿估计后轴速度，发布标准消息与健康状态 | 发布第二套定位 TF，读取仿真真值辅助控制 |
| `motion_guard` | 唯一运动控制出口、方向/曲率/时效检查、停止、优先级与租约 | 用裁剪掩盖不可行路径 |
| sim/real adapter | 标准速度/舵角语义到具体驱动协议的转换与超时停车 | 重新决定去哪 |

move_base 仅处理公共区动作，使用上述两个自定义封装插件。通道动作执行时，取消/停用 move_base 当前目标并撤回其控制租约，不能让它继续后台抢发速度。

### 6.2 必须保留的 action 语义

以现有 `ExecuteMotion.action` 为起点，保留：mission_id、task_id、target_id、map_id/map_version、target_reference、target_pose、enforce_yaw、motion_mode、path_scope、column_id、region_id、phase、inspect、stop_at_goal。

新增结果错误码和反馈阶段字段，不重新定义同名字段单位。采用唯一合约版本；升级后重新生成 ROS 消息并同时部署客户端/服务端。

- AUTO：允许公共区计划中的前进与倒退组合，不等于可任意走遍地图。
- FORWARD_ONLY：只允许前进或停车。
- REVERSE_ONLY：只允许倒车或停车，保持任务要求的车头方向。
- `enforce_yaw=false`：目标 yaw 占位值不生效。从 72 个车头角度中先剔除终点车身不合法者，再按与当前姿态/下一目标的方向关系预排序。初次搜索最多尝试前 8 个候选，共享第 7 节总时间预算；扩展搜索再按序尝试余下候选。front→rear 转换随候选角度进行，不能先固定一个后轴目标。
- INSPECT 成功：导航停稳且巡检接口确认成功；仅到达不算完成。
- 导航失败、取消、旧任务反馈不能推进 C 会话索引。任务切换先撤销旧控制权，确认零输出和停稳，再授权新控制器。

任务上下文包含路径范围、地图版本和 mission/task 标识。应通过带确认的服务/内部接口送入规划器与控制器，收到一致的 context_id 后才发送 move_base 目标；不能依赖“先发个 topic，大概已经收到”的时序。

## 7. 公共区全局规划：多次前后调整

### 7.1 固定搜索配置

使用 SBPL `XYThetaLattice` 与 `ARAPlanner`。空间分辨率随当前地图为 0.05 m，航向离散先用 72 个方向。保持实际车头朝向；倒车路径的车头朝向不能被重写成移动切线方向。

原语文件必须按当前分辨率、R_plan、轮廓生成并带哈希。文件包含前进/倒车的直线或近直线动作及不同曲率的转弯动作，无横移、无原地旋转。原语只包含一种行驶方向，换向发生在原语衔接处。

原语生成采用离线 C++ 工具：前进原语用 OMPL 非对称 Dubins 连接；倒车原语在移动朝向旋转 π 的等价模型中生成，输出时恢复真实车头朝向及带符号曲率。筛选无长绕圈、半径合格的短连接，再采样为 SBPL 格式。生成范围按 0.20～1.50 m 路长搜索，至少覆盖每个航向的前后近直行和左右改变航向动作。

均匀离散角度中，并非每个方向都能用严格直线恰好到另一个栅格中心。对此使用曲率合格的小弧线接到合法格点，不能扭曲末端、伪造横移；不要求每个方向都有数学上不可能的精确格点直线。若动作覆盖不完整，扩大候选终点搜索范围，不填入原地转向动作凑齐。

终点必须与声明的栅格位置、航向一致，不允许把运动积分末端直接吸附到格点。程序自动验证曲率、连续性和方向；不同分辨率/半径不得复用旧文件。几何原语可以有曲率变化，执行前还要通过第 8 节舵角变化率与完整扫掠校验。

### 7.2 路线选择和换向代价

原生 XYTheta 状态没有“上一段挡位”，本项目不能声称只调一个 SBPL 参数就获得换向次数惩罚。

V1 固定做三类候选搜索：仅前进原语、含倒车且倒车原语代价倍数为 2、含倒车且倍数为 4。封装内部各持有一个独立 SBPL 实例/配置，不能靠修改已初始化实例的原语参数假设自动生效。三类各分配初始预算 1 s，类内的目标角度与边界连接候选共享预算；对得到的可行路线，按以下项目代价重评分：

```text
J = 前进总长度 + 1.5 × 倒车总长度 + 0.6 m × 换向次数
    + 0.3 × 沿路径积分的归一化贴障代价（按米计）
```

这是一组有限候选的工程选优，不宣称全局最优。路线需要多次调整时允许更多换向，不用一个随意的最大换向次数把可行路线直接删掉。执行超时按预计总行程和换向次数计算，另设无进展检测。

初版累计规划预算 3 s，失败时停车并做一次总预算不超过 10 s 的扩展搜索；区分 `PLAN_TIMEOUT` 和 `NO_PATH_IN_MODEL`。超时不是物理无解证明。

### 7.3 连续起终点、姿态和入口接入

离散路径不可直接作为精确停车结果。对实际起点、终点与临近离散状态，允许混合方向的候选用 Reeds–Shepp 生成连续连接，仅前进候选用 Dubins；按距离及朝向差枚举最多 20 个临近连接状态，检查完整车身和任务范围，保留连接中的行驶方向与换向点。默认连接长度上限 2 m，连接失败返回搜索尝试其他邻近状态。所有连接枚举、校验和搜索共享本次总预算，不能每个候选都再等 3 s。

Dubins / Reeds–Shepp 只提供车辆几何连接，不自动避障，所有连接都必须采样碰撞检查。起点连接不允许瞬间改变当前车头方向。候选起点状态、目标状态必须作为真正的 SBPL 搜索边界，在通过连续连接后才能接入路线，不能只在原路径末尾补一条未经校验的直线。

ALIGN 的最终 0.35 m 接入段固定为沿通道方向前进直线，终点为批准的准备位姿。搜索连接到这段直线起点，不能以倒车姿态“到点”后宣告入口对准成功。

全局封装最终输出完整连续路线。每个采样位姿带车头角度，换向处共享相同位姿但分属相邻方向段；发布可视化路径及带方向的调试消息。nav_core 接口仍输出 PoseStamped 序列，局部插件依据位移在车头轴上的投影恢复方向并交叉核验，不能依赖 Path 时间戳编码挡位。

SBPL 原始实现保留了位姿中的 theta，但没有任务换向合约；本项目封装补齐该语义。[上游路径输出实现][S4]

## 8. 公共区执行：有向分段 TEB

### 8.1 分段执行规则

`SegmentedTebPlanner` 实现 nav_core 局部插件，内部调用固定版本的 TEB。收到完整路线后按方向切分，仅将当前单向段交给 TEB，当前段目标为下一个换向点或最终目标。

固定设置原则：`global_plan_overwrite_orientation=false`，`cmd_angle_instead_rotvel=false`，`max_vel_y=0`，`min_turning_radius=R_plan`，`free_goal_vel=false`；V1 关闭同伦多轨迹切换和主动转向偏置恢复。完整车身模型必须显式加载，配置缺失时报错，不能退回点机器人。

同一条路径被重复 setPlan 时不重置已完成段。以路径内容、任务上下文及 plan_id 判定是否真正重规划；不同计划切换必须先停稳，清理旧 TEB 状态与未执行段。

move_base 初版关闭周期性全局重规划（planner_frequency=0），由失败/环境变化触发重规划；关闭默认旋转恢复和清空静态/语义禁行区的恢复动作。规划线程更新时执行器仍要管理“停止—新计划确认—继续”的交接。

### 8.2 必须开发的 TEB 定向与舵速封装

Kinetic TEB 默认支持正负速度，但原版不能直接保证本项目要求的“当前段只能一个方向”。尤其不能把 `max_vel_x_backwards=0` 当成硬禁止倒车开关；该版本源码对此发出警告。[速度限制源码][S5]

对本项目固定版本维护小范围补丁，新增 `required_direction`，将当前段允许的有符号速度区间用于优化；同时加入舵角变化率约束/代价。修改保存在项目源码与 patch 目录，不直接编辑 `/opt/ros` 后丢失记录。

优化后必须再次验证整条待执行轨迹：方向不反转、曲率不超过 1/R_plan、舵角变化率不超过标定值、整车不碰撞且不越过任务范围。软代价较低不等于通过硬校验。不合格时停车重规划，不靠把不合格指令剪成零后持续卡住。

指令层检查只能做最后防线；需要持续限幅才能跟踪的路线判为模型不匹配。改变速度时保持曲率一致，不单独剪掉 angular.z 而继续追原路径。

### 8.3 停稳、换向与曲率过渡

换向点先减速停车，以有效雷达速度估计确认 `|v|<0.02 m/s`、`|ω|<0.03 rad/s` 持续至少 0.3 s，再切换方向；没有新有效估计，不能因为重复收到旧零值而确认停稳。

换向时只改变行驶方向，车头姿态连续。起步时按舵机实际速度建立转角，不能假设从左打满到右打满只需一个控制周期。驱动如果支持停车打方向，可以先完成转角建立；不支持时以低速曲率过渡起步，过渡扫掠空间也必须通过检查。具体分支由标定结果 `steer_at_rest_supported` 固定，不在运行中猜测。

对原语/连接中的曲率突变，在时间化与 TEB 优化后检查可执行的转角过渡；若过渡侵入障碍，则原候选路线不可执行，交回全局选择其他路线。不能用几何折线有解替代实际执行有解。

轨迹碰撞采样满足：相邻采样整车任一点移动不超过 min(地图分辨率/2, 0.02 m)，并检查位姿之间的扫掠区域；不能只检查后轴点或几个稀疏轨迹点。检查多边形覆盖内部与边界，避免障碍完整落在车身投影内部却只因边缘无碰撞而漏检。

## 9. 通道内控制和巡检事件

### 9.1 控制器固定选择

使用后轴参考的双向 Pure Pursuit 跟踪当前列中心线，20 Hz 输出。路径顺序始终按当前任务移动方向排列；倒车前视点取车辆后方的路径点，车头 yaw 不加 π。曲率按后轴坐标计算，输出 `ω=v×κ`，v 符号由阶段锁定。

初始前视距离 0.35 m，进入最后停车范围时缩短到不小于 0.15 m；最终通过第 14 节偏差测试确定。禁止把正向控制器的速度直接改为负数而不调整路径索引和前视选择。

通道内允许小幅纠偏，不允许自由绕障。初始巡检前进速度上限 0.10 m/s，倒车 0.08 m/s；靠近目标降至 0.04 m/s 以内，再根据制动曲线停车。

### 9.2 模式切换与退出净空

ALIGN 转通道模式前，前轴到准备点位置误差初值 ≤0.04 m、中心线横向误差 ≤0.03 m、朝向误差 ≤3°，且车身前进通路通过检查。V1 先停稳交接；只有后续所有验收完成，才允许同向连续交接优化。

INSPECT 到达后保持零速等待巡检确认。PASS 沿当前方向通过到另一侧准备点；RETREAT 保持车头方向倒退至原准备点。退出后还必须确认车身具备公共区转弯净空，不能只凭前轴刚离开巡检区域就开启转场。

进通道前已发生较大朝向/横向偏差时，退回公共区重新 ALIGN。通道内发现偏差已经无法在余量内纠正时停车失败，不自动变更为 AUTO 或往返试探。若需要撤离，由任务层发明确的授权撤离动作。

### 9.3 中心点停车与播报

继续采用“前轴中点到达巡检中心即停车巡检”的业务设计，不增加独立前轮入区检测节点，也不需要额外轮传感器。

但目标容差与制动距离必须在该巡检区域内满足：

```text
允许的目标误差 + 定位/跟踪误差 + 延迟行程 + 制动距离
    < 巡检中心到对应驶出边界的可用距离
```

区域范围来自场地语义配置，不从示意图猜一个固定宽度。条件不满足就降低接近速度或提高停车精度，不修改巡检中心来掩盖问题。巡检位置误差初值 ≤0.03 m，朝向 ≤3°，仍需满足上述几何条件。

巡检接口按 `(mission_id, region_id)` 去重，任务指令按 `(mission_id, task_id)` 去重。重复发送相同巡检请求时应返回已完成结果，不能再次播报。借道和倒车经过已检区域，导航只能报告位置，不生成新的巡检事件。

收到巡检确认后才更新 inspected 集合并推进。超时停车并报告 `INSPECTION_TIMEOUT`，不自动跳过。无真实识别/播报接口时可用显式 mock 服务进行仿真，但测试报告必须标注 mock，不能称为实车业务完成。

## 10. 纯雷达速度接口与健康条件

### 10.1 lidar_odom_bridge

输入已有连续 `odom → base_footprint` 位姿与固定到后轴外参，输出 `/nav/odom`（nav_msgs/Odometry）：header.frame_id=odom，child_frame_id=nav_base。pose 表达后轴在 odom 中的位置；twist 表达后轴坐标系下的速度。

先将连续位姿转换到后轴，再做 SE(2) 增量速度估计，使用源时间戳并处理 yaw 跨 ±π。使用最近约 0.3 s 的有效样本做平滑估计；报告实际窗口延迟及协方差，不填“绝对精确”的零协方差。控制层采用有效更新率，不用重复旧数据伪造 20 Hz 新观测。

不对可能发生全局校正的 `/amcl_pose` 直接差分。现有雷达前端可提供连续位姿时无需新建定位算法；若实际仅暴露全局结果，应先从该前端导出连续局部增量，再接本桥接器，不增加轮式/IMU 依赖。

仿真 `/sim/ground_truth/odom` 只用于独立评估误差；控制器和速度桥不读取它。对应代码/ROS 图检查为验收项。[雷达匹配上游输入输出][S6]、[TEB 速度读取][S5]

### 10.2 V1 默认健康阈值

目标为激光/局部位姿有效更新率 ≥8 Hz，控制循环 20 Hz。源数据年龄初始上限 0.30 s；真实频率低于此目标时先降低速度并重新计算停止空间，通过独立验收后才调整阈值。

监控：scan、局部位姿、map→odom→nav_base TF、导航速度、控制租约、驱动指令时效。任何一个失效都输出零速，当前任务不报成功。定位重置或单次校正明显超过 0.10 m / 5° 时停车，重新校验任务位置并重规划。

仿真使用 ROS 时间处理传感器；指令失联与控制权租约另外使用单调墙钟。Gazebo 暂停、/clock 回退或节点卡死时，不因 ROS 时间不走而无限保留最后一条非零速度。恢复后重新确认数据和租约。

## 11. 代价地图、权限和最终运动检查

全局 costmap 使用 map，局部滚动 costmap 使用 odom；robot_base_frame 均为 nav_base。初始局部窗口 6×6 m、分辨率 0.05 m、更新 5 Hz；必须覆盖低速停车距离及倒车后的障碍观察范围。

固定层顺序：StaticLayer、ObstacleLayer、TaskScopeLayer、InflationLayer。scan 向前/后覆盖与机器人自遮挡按实际数据核实，不能根据“理论全扫描”就认为倒车制动区始终已知。未知空间初版不可行驶。

TaskScopeLayer 使用白名单式可行驶范围，每次任务切换清理上一个上下文的缓存，再在全局/局部两张地图上确认同一 context_id。物理墙、未知空间不会因为语义允许而被清空；语义禁行也不能被 obstacle clearing 或 recovery 擦掉。

SBPL 的完整 footprint 检查依赖正确膨胀配置：inflation_radius 至少覆盖该参考原点下的外接半径，软代价在相关范围不能提前为零。以**后轴原点**计算，不套用车体中心的半径。初值可设 0.90 m，但必须根据生成的实际包络复核。膨胀软代价不是把这 0.90 m 全设成不可通过。[上游特别说明][S1]

最终执行检查包括：

1. 身份、地图版本、任务上下文、源时间戳有效。
2. 当前命令符号与当前段匹配，速度/加减速度/舵速符合标定。
3. 非零速度时 `|ω/v| ≤ 1/R_plan`；近零速不允许原地旋转命令。
4. 结合转向动态、感知延迟、制动能力，预测至少到停车的扫掠区域无碰撞、不越权限边界。
5. 当前跟踪偏差未超限；超限停车，公共区重规划，通道内报告失败。

真实停车距离由标定确定。初期制动预测可用 `v×延迟 + v²/(2×可靠减速度)` 再叠加误差余量，不把示例减速度当作实测值。

## 12. 驱动适配与消息约定

规划/跟踪内部统一输出后轴参考的标准 Twist：linear.x 为 m/s，angular.z 为 rad/s；y 速度为零。TEB 保持 `cmd_angle_instead_rotvel=false`，不在同一个 angular.z 字段里混用舵角。

motion_guard 对通过检查的命令生成 AckermannDriveStamped，包含带符号速度、等效前轮舵角和时间戳；有效期和控制来源由内部租约管理，适配器同时检查消息时效。不把自定义租约字段伪装成标准消息已有字段。

转向换算为 `δ = atan(L×ω/v)`；v 接近零时使用受控的停车转角策略，不能除零。倒车的转向符号用实际测试验证，不能简单把前进时的左右指令整体照搬。

仿真适配器对接当前 `/sim/cmd_vel` 插件，明确其 v/ω 对应后轴运动学；若需要停车建立舵角，增加明确的带舵角接口并关闭旧接口的并发订阅。旧键盘、waypoint_nav 不得绕过 motion_guard 继续向底盘发送指令。

实车适配器由驱动组确认实际命令单位、中心/限位、换向协议、超时停止机制。历史 `/odo_vel` 是 Twist 类型，不代表存在可用于本项目的轮式 Odometry；本方案不使用它替代纯雷达速度桥。

控制优先级：急停/失效停止 > 人工接管 > 当前授权自主控制器。人工接管撤销自主租约；松开人工控制不自动恢复旧任务，需要明确恢复动作。命令有效期初值 0.25 s，失联保持停车。

## 13. 状态机与异常处理

```text
IDLE → VALIDATE → PLAN_PUBLIC → FOLLOW_FORWARD / FOLLOW_REVERSE
                                  ↘ STOP_AT_CUSP → FOLLOW_NEXT_SEGMENT
                 → ALIGN_VERIFY → CHANNEL_FORWARD → INSPECT_HOLD
                                                  → CHANNEL_FORWARD（通过）
                                                  → CHANNEL_REVERSE（退出）
                 → EXIT_CLEAR_VERIFY → NEXT_TASK → ... → END → DONE

任意运动阶段 → SAFE_STOP → REPLAN_PUBLIC / FAILED / CANCELLED
```

状态切换依据条件确认，不用“等两秒应该好了”代替停稳或定位有效判断。所有 V1 业务目标 stop_at_goal=true；重复借道路径上的普通点不停车。

固定处理策略：

| 情况 | 行为 |
| --- | --- |
| map/参数/任务编号不一致 | 拒绝任务，零输出 |
| 公共区暂时有障碍 | 停车等待最多 3 s；仍阻挡则在当前权限内重规划 |
| 公共区局部轨迹连续 1 s 不合格 | 停车，重新全局规划；单任务最多连续尝试 3 次，仍失败则报告失败 |
| 通道内障碍或跟踪偏差超限 | 停车保持，不自动反向、不自动绕行；任务层决定后续授权动作 |
| 有运动请求但 5 s 无有效路径进度 | 停车；区分换向等待、识别等待与真实无进展，前两者不误触发 |
| 感知/TF/速度过期 | 立即停止授权运动，数据恢复后先重新校验，不自动跳到下一任务 |
| 巡检接口超时 | 停车保留待确认任务，不重复播报、不视为成功 |
| 取消或人工接管 | 撤销控制租约，确认停止，返回取消结果 |
| 进程重启 | 默认 IDLE/SAFE_STOP；加载记录供恢复，不自动执行磁盘残留指令 |

日志至少包含 mission_id、task_id、plan_id、context_id、地图/车辆配置哈希、模式、当前段号/方向、位置和朝向误差、估计速度、最小净空、换向次数、停止/失败原因。错误码固定为 MAP_MISMATCH、INVALID_TARGET、SENSOR_STALE、TF_ERROR、PLAN_TIMEOUT、NO_PATH_IN_MODEL、TRAJECTORY_INVALID、TRACKING_ERROR、DRIVER_TIMEOUT、INSPECTION_TIMEOUT、CANCELLED 等，并保留人可读原因。

## 14. 分阶段实施与验收门槛

以下顺序固定。上一阶段门槛未通过，不进入后续实车自主运动；允许并行完成不依赖运动的代码和文档。

### P0：冻结可用定位与构建基线

工作：记录实际 ROS 图、参数、TF 发布者、地图哈希、源码版本；将纯雷达的运行配置归档到源码母本。修正构建清单对现有依赖的遗漏，新建仅启动导航的 launch；不重启/替换已工作的定位前端。

验收：导航启动前后 scan、map 和定位 TF 发布者不变；无新 IMU 依赖；可重建并恢复相同基线。归档运行日志与包版本表，不记录密码。

### P1：统一几何、点位、语义和标定

工作：建立 nav_base、车辆配置、轮胎包络、R_plan；补齐地图批次元数据和语义范围；生成/核对准备点与最终直线接入段。

验收：RViz 中前轴、后轴、车身、转向轮包络和墙体一致；任意地图旋转后通道朝向仍正确；全部点位和路径范围验证通过；实车动态标定项有记录，未确认项标为未确认。

### P2：雷达速度接口与唯一控制出口

工作：实现 lidar_odom_bridge、motion_guard、仿真适配器和实车协议对照表；先在静止和人工低速运动数据上验证。

验收：直行、倒车、左右转弯速度符号正确；后轴横向速度在合理误差内；无真值输入；感知过期/发布者停止/时钟暂停能撤销非零命令；两个控制源不能同时驱动车辆。

### P3：离线车辆全局规划

工作：原语生成与校验、TaskAwareSBPLPlanner、语义 costmap、连续边界连接、带方向路径与评估脚本。

验收：空地直行、90° 转弯、纯倒车、需要至少两次换向的窄区域找正均能给出经扫掠校验的路线；半径不足、墙体阻挡和禁行捷径的案例被拒绝。输出路线几何、方向、换向点和规划耗时，不以 RViz 看起来顺滑作为验收。

### P4：公共区闭环跟踪和换向

工作：SegmentedTebPlanner、方向/舵速补丁、停稳判断、轨迹动态验证、重规划交接。

验收：先单段前进/倒车，再两段换向，再多段调整；所有换向都经过有效停稳确认，车头 yaw 连续；无原地旋转、无越权区域，无因重规划重复从第一段执行。目标位置/朝向达到设定容差。

### P5：通道进入、停车、通过与倒退

工作：corridor_controller；从准备位姿进入两个巡检位置，再按 A/B 执行通过或倒退；对接 mock 巡检确认。

验收：前轴在目标中心容差内停稳；倒车阶段从未输出正向运动；经过已检点不重复巡检；退出后整车具有转场净空。碰到临时障碍只停车，不横向绕行。

### P6：接 C 巡检核心及完整十点任务

工作：ROS C++ 包装原 C 核心；正式 action server；任务/巡检去重与持久化；规划失败不跳任务。

验收：先运行现有 C 测试确认逻辑基线，再执行第 15 节布局。必须同时核对“顺序正确”和“每一段实车几何可行”。原有纯拓扑测试通过不代表导航通过。

### P7：实车低速迁移

工作：部署相同业务/导航包，仅替换 real adapter 和设备参数；真实地图批次导入；使用真实外部空间与实测转向/停车参数重跑相同测试。

验收：分别通过空地单动作、一个入口、相邻入口多次调整、整场巡检；每组记录位姿、命令、净空、方向、确认事件。仿真通过但实车未跑的项目保持“待实车验证”。

### P8：效率优化

仅在正确性通过后进行：沿已验收同向段取消不必要中间停车、评估不同准备候选、按测得转场时间改进高层代价。核心比较指标为完整任务时间、换向次数和停车等待时间，必须同时保持成功率和最小净空。

不要为了减少路线米数而强行增加换向；不要把增大速度当作第一项优化。C 核心当前基于列号距离的选择可先保留；后续使用实际导航可行性/耗时矩阵优化时，保留原巡检去重和 A/B 拓扑约束。

## 15. 必做测试与通过标准

### 15.1 几何与导航用例

| 测试 | 必须观察到的结果 |
| --- | --- |
| 一个目标在车后方 | 正确规划倒车或合法调整，不原地旋转 |
| 单次圆弧无法对准、但多次前后调整可行 | 明确出现换向点并逐段停稳执行 |
| 真正空间不足的入口 | 停车并返回失败，不缩减 R_plan/footprint |
| 相邻通道转场 | 有车尾/车头扫掠检查；最终正向对准目标入口 |
| 长车身贴近隔墙端部 | 后轴点无碰撞但车身会碰撞的路径必须被拒绝 |
| 起终点不落在栅格和离散航向上 | 连续连接到真实目标；无坐标吸附或到点爬行转向 |
| 有更短的巡检区捷径 | PUBLIC_ONLY 下始终拒绝 |
| 倒车段遇障碍 | 停车，不擅自改成前进脱困 |
| 短暂停车后重新规划 | 不重放已完成巡检、不丢失当前方向状态 |
| 激光停止/TF 过期/控制源退出 | 在超时阈值内撤销运动并保持零命令 |
| 地图版本变化、取消、重复反馈 | 旧计划不执行、旧反馈不推进 |
| Gazebo 暂停再恢复 | 没有遗留非零命令突然继续行驶 |

### 15.2 巡检布局

先用当前 C 程序为这些输入生成预期业务顺序，保存为测试数据；不要凭本文件手抄预期路线替代算法输出：

```text
A1A2A3A4A5A6A7A8A9A10
B1B2B3B4B5B6B7B8B9B10
A1B2A3B4A5B6A7B8A9B10
B1A2B3A4B5A6B7A8B9A10
A1A2B3B4A5B6A7B8A9B10
B1B2A3A4A5A6A7A8A9A10
```

同时保留 A1B2A3B4 等短输入回归。全十点任务检查：每个要求巡检的点恰好一次确认；所有借道 inspect=false；B 区没有被继续穿越；最终到达导入的 end。

若任意布局的拓扑路线在真实几何下不可执行，记录具体有向转场失败边；高层可以屏蔽该边后按原规则重算，所有候选均失败才报告本地图/半径配置下任务不可行。不能对同一个失败动作无限重试，也不能直接略过巡检点。

V1 仿真门槛：以上六种布局各连续 10 次，在不同合理初始误差和激光噪声下，无碰撞、无错误方向、无重复播报、无任务跳过。应完成的可行用例全部完成；刻意构造的不可行/失效用例正确停止。先分别测试入口横向 ±0.03 m、朝向 ±3° 扰动，再测试组合边界。

记录全程用时、总长度、倒车长度、换向次数、最小几何净空、最大跟踪误差、停车误差和失败原因。实车重复次数按现场时间至少每个核心动作 3 次，通过前不解除低速限制。

## 18. 来源与结论边界

本文件的分层、控制权、阈值初值、任务规则及验收门槛是针对本车提出的工程设计；不把这些自定义要求归为开源库自带功能。

- 已核实：本地 C 核心/动作合约、旧导航草稿、26 点数据、静态启动/构建文件；相关开源 Kinetic 发布记录及关键源码。
- 未核实：此刻实车/容器中实际运行版本、动态标定值、现实场地转向净空、所有新增模块的编译与闭环效果。
- 已有尺寸不再重复猜测；无法从现有信息确定的动态量和场地边界在 P0/P1 填写。缺数据只阻止对应验收，不允许接手者自行填成已测结果。
- 不承诺任何半径车辆都能在任意小空间完成多次调整；本方案要求规划器给出可执行路线，或明确失败原因。
