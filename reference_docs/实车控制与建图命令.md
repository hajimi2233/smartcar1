## 二、先理解这台车的命令含义

```text
linear.x == 0：发送 stopRobot，电机控制量清零，舵机回 middle_angle。
linear.x != 0：电机控制量 = int(3000 × linear.x)。
舵机目标值 = int(2110 - 652 × angular.z)，再经过源码的边界处理。
```

例如 linear.x=0.05 对应约 150 的电机指令，不代表 0.05 m/s；angular.z 直接影响舵机，不是车体角速度。正负运动及左右转向必须现场验证，不能据注释断言方向。linear.x=0 时，即使 angular.z 非零，也会进入停车回中分支，不能靠“零速度、大角度”验证转向。

源码订阅 `/joy`，但无手柄时不需要向它发消息。`/odo_vel` 发布类型是 Twist，来源是旧试验性计算，不是 `nav_msgs/Odometry`，也没有看到该底盘代码发布 TF。第一次建图仍用纯雷达，不能把 odo_vel 简单改名为 odom。

**源码没有命令超时停车逻辑。** 旧键盘没有松键停车、没有幅值上限，q 在发零前直接退出。SSH 断开、键盘窗口关掉或停止 rostopic 发布，均不能视为车已停止。底盘构造 / 正常析构有 stopRobot，但进程强杀、通信故障不保证执行。第一次验证需现场人员守住急停；软件停车后仍以实际车轮状态确认。

## 四、不用手柄：按终端顺序启动

### 终端 A：ROS Master

```bash
roscore
```

保持此终端打开。如果此前已有 Master，先核实再复用，不重复启动。

### 终端 B：只启动底盘

先按急停并核对接线。当前设备枚举：

```text
/dev/ttyUSB0 ← Silicon Labs CP2102，序列号 0002
/dev/ttyUSB1 ← 1a86 USB2.0-Serial
```

这是芯片枚举，结合现有 launch 推测分别对应雷达 / 底盘，仍要现场确认实际 USB 线。当前两串口已经允许读写，不需重复 chmod；重插后重新检查。

```bash
ls -l /dev/ttyUSB* /dev/serial/by-id/
rosrun simple_controller simple_controller _ttyusb_port:=/dev/ttyUSB1
```

这里 `_ttyusb_port` 是 ROS 节点私有参数，前面有一个下划线。此命令不启动 joy_node，不需要手柄。程序打开串口时按源码会发送停车回中包，因此启动也会与硬件通信；本轮未替用户执行。

观察 `Serial Port initialized`；若出现错误，立即排查设备对应和占用，不继续发运动指令。日志可能很密集，保留错误输出即可，不要以日志滚动代替通信验证。

### 终端 C：检查连接并准备软件停车

```bash
rosnode info /simple_controller
rostopic info /cmd_vel
rostopic type /cmd_vel
```

应看到 simple_controller 订阅 `/cmd_vel`，类型 Twist。此时尚未启动控制输入，发布者为空可以是正常的。禁止同时运行旧 follow_object、其他自动控制器或另一份键盘程序。

**停车命令：**

```bash
rostopic pub -r 10 /cmd_vel geometry_msgs/Twist \
  '{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}'
```

它持续发布零指令。确认车停后 Ctrl+C 结束发布；启动下一项运动测试前不要保留这个零发布器与运动发布器互相覆盖。若已有其他运动源，先在其终端停止它；任何失控先用物理急停，零发布器不是多源控制仲裁器。

### 终端 D：运行已有键盘程序

```bash
python /home/smartcar/catkin_ws/src/teleop/src/keyboard.py
```

该程序使用 Python 2 语法，在这台机器 `python` 已确认是 2.7.12。不要改用 python3。SSH 的交互终端可以接受按键，不需要 GUI 或 DISPLAY。

| 按键 | 源码实际效果 |
|---|---|
| w / W | 累计速度变量 +1，即 linear.x 每次 +0.1 |
| s / S | 累计速度变量 -1，即 linear.x 每次 -0.1；不是无条件停车 |
| a / A | 转向变量 +1，即 angular.z 每次 -0.2 |
| d / D | 转向变量 -1，即 angular.z 每次 +0.2 |
| 空格 | 未匹配按键分支，速度与转向都清零并发布 |
| q（小写） | 直接 exit，没有先发送停车包 |
| z / c | 转向变量直接 ±7，即 angular.z 为 ∓1.4，初次测试不要使用 |

大写 WASD 与小写效果相同，提示中的 Caps 加速不符合现有实现。按住会受键盘连发影响持续累加，松键不会复位。显示 10 Hz 的 rate 也不意味着持续发包：程序阻塞等待一个按键，之后才发布一次。

第一次先空格，再在现场人员准备好时短按一次 w，确认实际方向和力度后马上空格。转向需要非零行驶量配合，避免首次在狭窄巷道验证。正常退出固定为：**空格 → 观察车确实停止 → q**。若按键显示异常，可回到正常 shell 用 `stty sane` 恢复终端。

这个键盘可以验证旧接口，但其步长和无失联保护不适合作为长期建图遥控方案。正式持续建图前应补限幅、超时停车和可靠退出流程，尤其应在底盘接收侧实现 watchdog；本轮不改驱动源码或二进制。

## 五、精确发布单个控制值的命令

仅在底盘连接及停车测试通过后执行，并先退出键盘，确保只有一个运动发布器。以下 0.05 是较旧键盘单次步长更小的测试指令，**不是已标定安全速度**。

正向指令示例：

```bash
rostopic pub -r 10 /cmd_vel geometry_msgs/Twist \
  '{linear: {x: 0.05, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}'
```

非零转向示例（实际向左还是向右先验证）：

```bash
rostopic pub -r 10 /cmd_vel geometry_msgs/Twist \
  '{linear: {x: 0.05, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.1}}'
```

反向仅在已核实下位板支持并具备倒车空间时，把 linear.x 改为 `-0.05`。不要无上限加大幅值来克服静摩擦。

结束任一运动发布：Ctrl+C 停发布，然后立即执行第四节停车命令并确认停车。**Ctrl+C 本身不发送零。** 这些命令供接口验证，不用于无人看护运动；不要仅用 timeout 包住运动 rostopic 命令就认为超时会停车。

可在检查终端运行 `rostopic echo /cmd_vel` 观察实际指令，但收到 ROS 消息不代表电机或舵机已按指令执行。
